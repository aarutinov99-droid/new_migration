================================================================================
1. НАЗНАЧЕНИЕ
================================================================================
Скрипт предназначен для проверки функционала идентификации ПДЛ (публичных
должностных лиц) в спецреестре ЕОР. Проверяется сценарий, когда запись ПДЛ
не имеет связи с субъектом ЕОР и требуется её установить.

Скрипт покрывает:
  - добавление данных в Спецреестр ПДЛ;
  - изменение данных в Спецреестр ПДЛ;
  - обе ветки обработки: РФЛ (l_is_rfl = 1) и ИФЛ (l_is_rfl = 0);
  - обе ветки эталонности: etalon_sign = '1' и etalon_sign = '0';
  - создание упоминаний (idw_mr_subject_mention) и атрибутов
    (rfl_attr_src / ifl_attr_src);
  - создание/обновление sr_subject, sr_event, sr_subject_h;
  - установку флага is_eor_ident_process = 1;
  - полный цикл: загрузка -> прогон -> контроль -> откат.

7. ИДЕМПОТЕНТНОСТЬ
================================================================================
  - Все INSERT защищены WHERE NOT EXISTS - повторный запуск не даёт дублей.
  - UPDATE в блоке 2 защищён условием COALESCE(countries,'') <> 'КАЗАХСТАН'.
  - Блок 5 проверяет наличие истории в sr.sr_subject_h перед созданием

  - Блок 1.4 использует ON CONFLICT (id) DO NOTHING для test_eor_subject_id
    и NOT EXISTS для очереди.
  - CREATE TABLE IF NOT EXISTS - безопасно при повторном применении.

       и sr.sr_subject_pdl.

  8.4. Блок 6 - DROP TABLE IF EXISTS eor.test_eor_subject_id;
       DROP TABLE IF EXISTS eor.test_eor_subject_process;

  Откат скрипта изменений (fors_change_db_func.sql) не предусмотрен.
  Записи workflow/состояний/process_state создаются идемпотентно
  (ON CONFLICT DO NOTHING) и не удаляются.


================================================================================
9. ЗАМЕЧАНИЯ И ПРЕДУПРЕЖДЕНИЯ
================================================================================
  1. Блок 5 содержит закомментированный INSERT INTO sr.sr_subject_h -
     предзаполнение истории отключено намеренно. Контроль ожидает
     sr_subject_h = 0 до прогона процедуры.

  2. Блоки 4.4 / 4.5 используют WITH ... DELETE ... RETURNING -
     CTE-удаление зависимых атрибутов до удаления упоминаний.
     Порядок важен.

  3. Блоки 4.6 -> 4.7 -> 4.8 - порядок удаления sr_subject_h -> sr_event ->
     sr_subject обусловлен FK-связями.

  4. Блок 5.6 по умолчанию закомментирован - опорные данные (sr_subject_pdl,
     буфер) остаются для повторных прогонов.

  5. Синхронизация sr.sr_event_seq выполняется в блоке 5 автоматически:
     если last_value < MAX(sr_event_id), последовательность выравнивается
     через setval.

  6. Идемпотентность блока 4 - повторный запуск отката безопасен
     (повторное удаление вернёт 0 строк).

  7. CURRENT_USER используется в sr.sr_event.sr_event_user и
     sr_event_user_os - при запуске под сервисной учётной записью
     значения будут соответствующими.

  8. Логическая правка в pr_pdl_ident_batch (в fors_change_db_func.sql):
     закомментирован повторный блок IF l_is_rfl = 0 для
     add_subj_ifl_mention.
