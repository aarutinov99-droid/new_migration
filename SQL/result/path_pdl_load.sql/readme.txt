================================================================================
ИНСТРУКЦИЯ ПО ТЕСТИРОВАНИЮ ЗАГРУЗКИ ПДЛ В СПЕЦРЕЕСТР ЕОР
Скрипт: pr_eor_pdl_load.LOAD.sql
================================================================================

ЧТО ДЕЛАЕТ СКРИПТ
-----------------
Скрипт pr_eor_pdl_load.LOAD.sql — это тестовый сценарий для проверки процесса
загрузки архивного слоя ПДЛ (персональных данных лиц) в спецреестр ЕОР.

================================================================================
ПРЕДВАРИТЕЛЬНЫЕ УСЛОВИЯ
================================================================================

Перед запуском скрипта необходимо:

1. Настроить архивный слой (arch_pg)
   - Выполнить скрипт archi_change_full.sql
   - Загрузить тестовые данные: test/archi_pr_eor_pdl_load_data_test.sql

2. Настроить операционный слой (fors_pg)
   - Выполнить скрипт fors_change_full.sql
   -  Выполнить скрипт fors_change_function.sql (фукционал)

================================================================================
ЭТАП 1. ПОДГОТОВКА ДАННЫХ
================================================================================

Шаг 1.4. Создание таблицы eor.test_eor_subject_id
         - Опорная таблица с 6 тестовыми субъектами (id 1–6)

Шаг 1.5. Вставка в arch_ext.idw_sy_workflow_info
         - Постановка субъектов в очередь архивного слоя
         - workflow_id = 225, state_id = 2251

Шаг 1.6. Создание eor.test_eor_subject_process
         - Таблица для фиксации времени начала/окончания процесса

================================================================================
ЭТАП 2. ЗАПУСК ПРОЦЕССА
================================================================================

Выполняется анонимный блок DO $$, который:

1. Запускает процесс через process_manage.start_process
   с типом PR_EOR_PDL_LOAD_PG
2. Фиксирует ID процесса в test_eor_subject_process
3. Вызывает eor.pr_eor_pdl_load — ОСНОВНОЙ ПРОЦЕСС ЗАГРУЗКИ ПДЛ
4. Завершает процесс через process_manage.finish_process
5. Фиксирует время окончания

================================================================================
ЭТАП 3. ПРОВЕРКА РЕЗУЛЬТАТОВ
================================================================================

Скрипт выводит следующие проверки:

--------------------------------------------------------------------------------
Проверка                                         | Ожидаемый результат
--------------------------------------------------------------------------------
Логирование (process_info.tbltracer)             | Трассировка процесса
eor.test_eor_subject_id                          | 6 субъектов
process_info.process_state                       | Настройки PR_EOR_PDL_LOAD_PG
arch_ext.idw_arj_interfax_pdl_load_buffer        | Буфер изменений
sr.sr_subject_pdl                                | Записи спецреестра
Архивная очередь (225/2251)                      | ДОЛЖНА БЫТЬ ПУСТА (0)
Очередь FORS (225/2252)                          | ДОЛЖНА ПРИСУТСТВОВАТЬ
Ошибки (idw_sy_workflow_error)                   | ДОЛЖНЫ ОТСУТСТВОВАТЬ
--------------------------------------------------------------------------------

СВОДНЫЕ МЕТРИКИ — 6 показателей с количеством записей:

  1. Всего субъектов для обработки
  2. Записей в буфере изменений
  3. Записей в архивной очереди (должно быть 0)
  4. Записей в очереди FORS state=2251
  5. Записей в очереди FORS state=2252
  6. Ошибок обработки

ИТОГОВЫЙ РЕЗУЛЬТАТ:
  - TEST PASSED            — если архивная очередь пуста,
                             очередь FORS 2252 заполнена, ошибок нет
  - TEST FAILED - NEED ANALYSIS — в противном случае

================================================================================
ЭТАП 4. ОТКАТ (ОЧИСТКА ДАННЫХ ПРЕДЫДУЩЕГО РАСЧЁТА)
================================================================================

Удаляются все созданные тестовые данные:

  1. Ошибки расчёта (process_info.idw_sy_workflow_error)
  2. Архивная очередь (arch_ext.idw_sy_workflow_info)
  3. Очередь FORS (process_info.idw_sy_workflow_info)
  4. Дочерние таблицы буфера PDL (8 таблиц):
       - idw_arj_pdl_categories_buffer
       - idw_arj_pdl_category407_buffer
       - idw_arj_pdl_countries_buffer
       - idw_arj_pdl_jobs_buffer
       - idw_arj_pdl_names_buffer
       - idw_arj_pdl_sanctions_buffer
       - idw_arj_pdl_sanlists_buffer
       - idw_arj_pdl_translit_names_buffer
  5. Основная таблица буфера idw_arj_interfax_pdl_buffer
  6. Опорная таблица буфера idw_arj_interfax_pdl_load_buffer
  7. Удаление опорных таблиц:
       - eor.test_eor_subject_id
       - eor.test_eor_subject_process

ДОПОЛНИТЕЛЬНО требуется выполнить очистку тестовых данных в архивном слое:
  - test/archi_pr_eor_pdl_clear_data_test.sql

================================================================================
ЛОГИКА ПРОЦЕССА (ЧТО ПРОВЕРЯЕТСЯ)
================================================================================

        Архивный слой (225/2251)
                |
                v
    +-----------------------+
    |  eor.pr_eor_pdl_load  |  <-- основной процесс
    +-----------------------+
                |
                +---> Буфер изменений (idw_arj_interfax_pdl_load_buffer)
                |
                +---> Спецреестр ПДЛ (sr.sr_subject_pdl)
                |
                +---> Очередь FORS (225/2252)  <-- субъекты переведены
                                                     в новое состояние

КРИТЕРИЙ УСПЕХА:
  Субъекты уходят из архивной очереди (2251),
  попадают в очередь FORS (2252),
  спецреестр ПДЛ обновляется, ошибок нет.
